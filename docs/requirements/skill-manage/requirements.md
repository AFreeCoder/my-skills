# Skill 管理 Skill 需求

日期：2026-07-16

## 背景

自建 Skill 由 [AFreeCoder/my-skills](https://github.com/AFreeCoder/my-skills) 集中维护，
本机权威目录为 `/Users/afreecoder/project/my-skills`。日常仍需要根据用户要求，把 Skill
安装到单个项目或用户级环境，并持续维护自建 Skill 与第三方 Skill 的可发现清单。

## 目标

- 提供统一的 Skill 管理入口，识别用户是在安装、更新还是维护清单。
- 按用户明确要求选择项目级或用户级安装范围。
- 保持自建 Skill 的来源、展示清单和实际库存一致。
- 保持第三方 Skill 收藏清单可核对、可更新、无重复。
- 对可能覆盖、删除、全局安装或推送远程的操作保留清晰边界。

## 非目标

- 不把第三方 Skill 源码复制进 `my-skills` 仓库。
- 不把 `my-skills` 扩张成第三方 Skill 包管理器。
- 不自动清理用户级或项目级已有 Skill。
- 不在用户未明确要求时自动提交、推送或发布清单变更。

## 业务规则

1. 自建 Skill 的唯一事实源是 `AFreeCoder/my-skills` 及其本地权威目录。
2. 用户未明确安装范围时，默认使用项目级；用户级安装必须由用户明确表达。
3. 项目级自建 Skill 优先复用本地权威源码，避免产生新的源码副本。
4. 第三方 Skill 只维护来源清单，安装与更新仍遵循其上游工具和说明。
5. 名称冲突、已有普通文件或目录、未知来源、工作区脏状态必须先报告，不覆盖。
6. 删除、批量迁移和全局清理必须先只读审计，并在用户确认后执行。

## 验收方向

- 用户可明确要求把指定 Skill 安装到项目级或用户级，并能得到安装结果验证。
- 新增或修改自建 Skill 后，仓库对外清单与实际目录保持一致。
- 第三方 Skill 清单可新增、修改、移除并通过结构与冲突校验。
- Skill 能区分“更新权威源码”与“更新已安装第三方 Skill”。
- 默认流程不会静默覆盖冲突路径，也不会未经授权推送远程。
