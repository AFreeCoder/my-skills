# GPT101 Dashboard 周更新

将当前 Dashboard 归档到每周回顾目录，并生成新一周的 Dashboard。

## 参数

$ARGUMENTS

- `--analyze`：（可选）输出历史周回顾的问题分析

## 路径定义

- Vault：`/Users/afreecoder/Nutstore Files/工作空间/我的笔记`
- 项目目录：`{Vault}/10_Project/GPT101`
- Dashboard：`{项目目录}/00-Dashboard.md`
- 归档目录：`{项目目录}/03-每周回顾`
- 模板：`{Vault}/99_System/Templates/Project-Dashboard.md`

## 执行步骤

### 1. 读取当前 Dashboard

读取 `{项目目录}/00-Dashboard.md`，提取以下信息：
- 当前周数和起始日期（从「本周焦点」标题解析，如 `W05: 1/27 起`）
- 本月北极星目标
- 结果目标及实际达成值（从「周末回顾 > 指标达成」表格提取）
- 杠杆目标设定
- 经验教训
- 下周重点

### 2. 归档前检查

检查「周末回顾」部分是否已填写：
- 查找「## 完成情况」下是否有实际内容（不只是模板占位符）
- 查找「## 指标达成」表格是否有实际数值

**如果未填写：**
提醒用户："当前 Dashboard 的周末回顾尚未填写，建议先完成回顾再归档。是否继续？"
等待用户确认后继续。

### 3. 计算日期信息

执行以下命令获取时间信息：
```bash
date "+%Y-%m-%d"     # 今日日期
date "+%V"           # ISO 周数
date "+%Y"           # 年份
```

计算新一周信息：
- 新周数 = 当前周数 + 1（如 W05 → W06）
- 新周起始日期 = 当前周起始日期 + 7 天
- 如果跨月，更新月份

### 4. 归档当前 Dashboard

归档文件命名格式：`W{周数}-{年}-{月}-{日}.md`
- 示例：`W05-2025-01-27.md`

将当前 Dashboard 完整内容复制到：`{归档目录}/{归档文件名}`

### 5. 提取上周实际数据

从刚归档的文件中提取「周末回顾 > 指标达成」表格的实际值：
- 单日订单峰值实际值
- 访问量实际值
- 其他自定义指标

这些值将用于新 Dashboard 的「上周实际」标注。

### 6. 读取模板

读取 `{模板路径}`，获取 Dashboard 基础结构。

### 7. 生成新 Dashboard

结合模板和上周数据，生成新一周的 Dashboard：

**保持不变的部分：**
- 本月北极星（除非跨月，则需要用户确认是否更新）

**自动更新的部分：**
- 本周焦点：更新周数和日期（如 `W06: 2/3 起`）
- 结果目标：基于上周实际值设定新目标
  - 建议逻辑：如果上周未达标，新目标 = 上周实际 × 1.25（保守增长）
  - 如果上周达标，新目标 = 上周目标 × 1.15（适度挑战）
- 杠杆目标：继承上周设定 + 上周「下周重点」内容
- 里程碑：重置为未完成状态
- 行动清单：根据杠杆目标重新生成，清空完成状态
- 关键指标：清空当前值，保留目标列
- 风险与阻塞：继承上周经验教训作为警示
- 周末回顾：重置为模板占位符

### 8. 写入新 Dashboard

将生成的内容写入 `{项目目录}/00-Dashboard.md`，覆盖原文件。

### 9. 可选：历史分析

如果参数包含 `--analyze`：
1. 读取 `{归档目录}` 下所有历史回顾文件
2. 汇总分析：
   - 各周目标达成率趋势
   - 重复出现的经验教训（问题模式）
   - 杠杆目标执行情况
3. 输出分析报告，指出当前最大问题

### 10. 输出结果

报告执行结果：
```
✅ Dashboard 周更新完成

📁 归档文件：03-每周回顾/W05-2025-01-27.md
📄 新 Dashboard：W06 (2/3 起)

📊 上周实际 → 本周目标：
- 单日订单峰值：32 → 40
- 访问量：158 → 200

⚠️ 继承警示：
- {上周经验教训}
```

## 使用示例

```
/gpt101-dashboard-renew
```
→ 归档当前周，生成新一周 Dashboard

```
/gpt101-dashboard-renew --analyze
```
→ 归档 + 生成 + 输出历史问题分析

## 注意事项

1. **跨年处理**：如果从 W52 跨到 W01，年份需要 +1
2. **跨月处理**：如果新一周跨月，提示用户是否更新北极星目标
3. **数据验证**：如果上周实际数据缺失，提示用户手动输入
