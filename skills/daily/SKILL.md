# Obsidian 每日工作记录

目标：把当前会话的工作内容写入当日日志。所有记录统一写入**每日流水**，不区分类型。优先保证定位准确、格式一致、可追溯，并且**记录尽可能详细，尤其是过程，要能串起来，确保连贯**。

## 核心流程

1. **解析写入内容**
   - 读取用户输入，提取要记录的内容。
   - 内容要求包含：**事项摘要 + 起因 + 过程明细 + 结论/产出**。
   - **过程详细度要求（必须遵守）**：
     - 过程步骤必须**按时间顺序**排列，前后步骤之间有因果或递进关系，读者能从头到尾串起整个脉络。
     - 每个步骤写明：谁做了什么、为什么这么做、产出了什么。
     - 遇到问题/转折/决策时，必须记录：遇到了什么问题、尝试了什么方案、最终选了哪个及原因。
     - 涉及代码/配置变更时，列出关键文件路径、修改点、影响范围。
     - 涉及外部项目/资源时，补充项目地址或参考链接，便于后续跳转与理解。
   - **主语规则（必须遵守）**：
     - 每个步骤必须明确主语，不能省略。
     - 工具/助手执行的操作，必须写明工具名：`Codex`、`Claude Code`、`ChatGPT` 等。
     - 用户执行的操作：可写"用户"，也可以省略主语。

2. **获取时间与路径**
   - 今日日期：`date "+%Y-%m-%d"`
   - 当前时间：`date "+%H:%M"`
   - 当前项目：优先取用户给定名称；否则从当前工作目录提取目录名作为默认项目名
   - 日记路径：`/Users/afreecoder/Nutstore Files/工作空间/我的笔记/90_Daily/{YYYY-MM-DD}.md`

3. **确保日记文件存在**
   - 若文件不存在：从模板复制
     - 模板：`/Users/afreecoder/Nutstore Files/工作空间/我的笔记/99_System/Templates/Daily Note.md`
   - 如模板含 `{{date}}` 变量，替换为今日日期。
   - 若模板也不存在：创建空白日记，包含 `# 一、每日流水（所思所想 / 随手捕获）` 标题。

4. **生成详细记录草稿**
   - 先回顾当前会话，按时间线整理：做了什么、为何要做、关键步骤与决策、遇到的问题与解决方案、最终产出/结论。
   - **连贯性检查**：草稿写完后自查——从第一步到最后一步，读者能否不跳跃地理解整个过程？如果有断裂，补充衔接说明。
   - 列出关键文件、指令、修改点、产出链接、影响范围等。
   - 主语不足时，补全为 `Claude Code`（或用户明确提到的工具名）。

5. **追加写入每日流水**
   - 追加到 `# 一、每日流水（所思所想 / 随手捕获）` 的列表中。
   - 格式：
     ```
     - {HH:MM} | {事项名称概括} #标签
     	- 起因：{为什么要做这件事}
     	- 过程：
     		1. {主语} {动作1}，{原因/背景}
     		2. {主语} {动作2}，{承接上一步的逻辑}
     		3. 遇到{问题}，{主语} 尝试{方案}，最终{结果}
     		4. ...（按实际步骤展开，不省略关键环节）
     	- 结论：{结果/产出链接/后续计划}
     ```

6. **写入前回顾与确认**
   - 先给出简短总结：事项摘要、关键过程、结论。
   - 预览写入内容，确认后再落盘。

## 与本仓库关联的技能

- `obsidian-markdown`：编辑 .md 日志，确保 Obsidian 语法与双链格式正确。
- `obsidian-bases`：如涉及 `.base` 视图或统计时使用。
- `json-canvas`：如涉及 `.canvas` 图形笔记时使用。

## 失败与兜底

- 找不到模板 → 创建空白日记并写入流水条目
- 内容过于简略/缺少起因过程结论 → 先基于当前会话补全，再向用户确认
- 过程步骤不连贯/有跳跃 → 补充衔接说明后再写入
